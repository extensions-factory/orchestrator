Saved Filters Implementation Plan

For agentic workers: Execute each task with TDD and stop at every User Story checkpoint.

Spec: docs/superpowers/features/saved-filters/design.md

Goal: Let support agents save, restore, and delete personal ticket filters.

Architecture: Persist canonical ticket-query strings behind a small ownership-checked API, then reuse the existing query parser when applying them.

Tech Stack: TypeScript, React, PostgreSQL, Vitest, Playwright

Expected Outcome

Working behavior

  • US-1: agents can save and restore a multi-condition ticket filter.
  • US-2: agents can delete a saved filter without changing active results.

Artifacts

  • saved-filters.ts owns persistence and validation.
  • SavedFiltersMenu.tsx provides save, apply, and delete controls.

How to see it working

Run npm run test:e2e -- saved-filters; observe a saved five-condition queue restored in a fresh browser session.

Global Constraints

  • No new runtime dependencies.
  • The existing ticket-query parser remains the single source of truth.
  • Every API operation enforces account ownership.
